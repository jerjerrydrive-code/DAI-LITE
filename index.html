Endpoint blocked by CORS? Known fixes

Browsers only allow cross-origin API calls when the server sends CORS headers. OpenRouter and NVIDIA already do, so their presets work as-is. If a request fails:

  • Ollama (local): start it so it allows this page's origin — OLLAMA_ORIGINS=* ollama serve (or set OLLAMA_ORIGINS to your exact origin).
  • Any endpoint without CORS headers: run a throwaway Chrome — chrome --disable-web-security --user-data-dir=/tmp/dai — or put a tiny local proxy in front that adds Access-Control-Allow-Origin.
Device & connection

DAI-LITE speaks a simple text CLI to a device. Connect over Bluetooth, or over WiFi to a WebSocket serial bridge (e.g. an ESP32 or a PC left running) so you can leave it plugged in like an AIPI Lite.

Your bridge must expose a WebSocket that relays text to/from the device's serial port. Note: an https:// page can only reach wss:// — serve DAI-LITE over http/localhost to use plain ws://.
Voice

On-device voices are free but robotic. For natural, realistic voices use a neural TTS provider (OpenAI-compatible /audio/speech) — this needs a TTS-capable key. OpenRouter does not do TTS.

Free realistic voices via Puter (no key). Loads the Puter SDK from js.puter.com on first use and sends reply text to Puter; it may ask for a quick sign-in. Won't work inside a locked-down/CSP sandbox.
Edge-TTS & FreeTTS need no key. Edge-TTS runs locally (see openai-edge-tts) — start it, then use its URL.

⚠️ Before you start

This app controls real RF and hardware. DAI-LITE can command a physical device to transmit radio signals, emulate access credentials, run scripts, and modify files. Transmitting on certain frequencies, cloning cards, or accessing systems you don't own may be illegal.

You are solely responsible for legal, authorized, and ethical use. Only operate hardware and signals you own or have explicit permission to test. Every command the assistant proposes must be confirmed by you with the Run button — nothing executes on its own.
